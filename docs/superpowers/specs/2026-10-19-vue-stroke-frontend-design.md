# 第 1 阶段设计：Vue 前端、笔画记录与身份水印

日期：2026-10-19

状态：已批准实施。

## 目标与范围

将现有网页迁移到 Vue，保留实时 CNN 分类、画笔、橡皮擦、颜色、粗细、清空、失败样本 PNG 导出、Top-5 排行、最近 10 次结果、延迟统计与类别列表。新增可重放的笔画记录，以及可编辑、在本机保存的学号和姓名。

用户已选择本轮只完成第 1 阶段；学号与姓名暂不填写。后端 Python 文件、CNN 权重、训练流程和 API 格式保持不变。本轮不安装或调用 Sketch-RNN，不实现续画、画龙点睛或视频录制。

## 用户最新约束

用户要求一轮直出：不编写或运行任何测试，不使用测试框架或测试命令，不验证哈希，不增加防御性编程。这些最新约束覆盖原设计中的自动化测试验收和存储异常降级要求；身份信息直接使用 localStorage 保存与恢复。

## 已核对的项目事实

- `backend/config.py` 固定首页为 `frontend/index.html`，静态目录为 `frontend/static/`。
- `backend/main.py` 提供 `/`、`/static`、`GET /api/health`、`GET /api/classes`、`POST /api/predict`。
- 预测请求为 `{ image_b64: "data:image/png;base64,...", top_k: 5 }`。
- 响应为 `{ predictions: [{ label, prob }], is_blank, guessed, latency_ms }`。
- 现有画板逻辑坐标为 280 × 280，实际显示尺寸随容器变化。
- 旧前端每 500 ms 检查一次，只在画面改变且没有进行中的请求时提交预测。
- 前端原有的稳定识别条件为最高概率至少 0.65，连续两次有效预测的最高类别相同；不直接以响应里的 `guessed` 替代这一条件。
- 仓库已包含 `artifacts/model.pt`；源码审阅与前端构建不代表已运行真实 CNN 推理。

## 技术选择

采用 **Vue 3 + JavaScript + Vite**，使用 `.vue` 单文件组件与 Composition API。Vue 官方将 Vite 作为单文件组件的推荐工具链，适合本次需要拆分模块、方便讲解的目标。[Vue 工具指南](https://vuejs.org/guide/scaling-up/tooling.html)

另一种可行方式是把 Vue 运行时放到本地静态目录，通过普通 JavaScript 模块加载。这能省掉构建，但单文件组件与后续扩展的组织方式不如 Vite 直接，因此本轮选择 Vite。

Vue 源码放在 `frontend/web/`，npm 配置和 Vite 配置放在 `frontend/`。Vite 先构建到独立的 `frontend/dist/`，再由 `frontend/publish.mjs` 将首页和资源复制到 `frontend/index.html` 与 `frontend/static/vue/`。输出路径通过 Vite 的 `outDir` 和 `assetsDir` 配置控制。[Vite 构建选项](https://vite.dev/config/build-options.html)

提交可用的构建产物，使既有 `python app.py` 启动方式继续能打开页面。前端开发时由 Vite 将 `/api` 代理到 `127.0.0.1:8000`。页面运行所需的 Vue、JavaScript 和样式全部来自本地，不依赖 CDN。

## 笔画记录与重放

数据源从“只有 Canvas 像素”改为“有序笔画记录”。Canvas 仍负责显示与生成分类 PNG。

每一笔包含唯一标识、工具类型、颜色、逻辑线宽、起止时间和按输入顺序排列的坐标点。坐标点包含 `x`、`y` 和相对于该笔开始的毫秒数 `t`。坐标统一落在 0–280 的逻辑范围内，不随 CSS 大小或屏幕像素密度变化。

- 按下主指针时开始一笔，移动时追加坐标，抬起时提交完整笔画。保留最终抬笔坐标。
- 仅点一下也要记录并绘制圆点。忽略右键及同时出现的其他指针。
- 使用 pointer capture，指针移出画板后仍能正确结束；`pointercancel` 或意外失去捕获时保留已显示的部分并结束本笔。
- 工具、颜色和粗细在开始一笔时确定，避免一笔内部样式与记录不一致。
- 橡皮擦保留为有序的 `eraser` 操作，用白色路径重放；JSON 明确标识工具，避免后续模块把擦除轨迹当成墨迹。将来续画所需的“擦除后的有效路径”转换属于后续阶段。
- 尺寸变化或设备像素密度变化时，从记录重画，不依赖旧像素截图保存内容。窗口变化不改变记录坐标和线宽。
- 清空同时清掉已完成笔画和进行中的笔画，并结束指针捕获。
- 增加“导出笔画 JSON”，包含格式版本、逻辑画板尺寸和有序记录，方便核对数据、后续续画和动画读取。本轮不增加 JSON 导入。

JSON 导出只包含画图数据；身份信息保存在单独的本机设置中，不混进画图数据或分类输入。

## 实时识别与状态一致性

继续每 500 ms 检查一次画面变化，每次提交白底 PNG 和 `top_k: 5`，同一时间最多一个预测请求。不在画面完全未变化时重复请求；接口失败后保留待识别状态，后续周期可重试。

用画面版本号标记变化，请求开始时记录它对应的版本；响应只能确认自己提交的版本，不得把请求过程中发生的新笔画标记为已识别。清空时切换画板会话并取消旧请求，即使旧响应最终返回，也不能恢复旧结果。

稳定识别继续要求连续两次有效、非空且最高概率至少 0.65 的响应有相同最高类别。空白结果、低置信度和清空会重置稳定计数。前端保留最近 10 次识别结果，以及最近 200 个延迟样本的均值和最大值。

页面卸载时清理请求、计时器、尺寸监听和指针状态。后端不可达、模型未加载、无墨迹、正在识别分别显示清晰状态；不能用模拟分类冒充真实模型结果。

## 界面与身份水印

保留“左侧画板、右侧识别结果”的桌面结构，窄屏改为上下排列。界面采用中文操作文案，保留后端返回的英文类别键，便于与 20 类模型对应。延续原页面暖色、圆角和轻量机器人反馈，不引入额外 UI 框架。

学号、姓名放在页面头部可见的身份卡片中，初始显示“学号未填写”“姓名未填写”，提供明确的编辑入口。填写后通过 localStorage 键 `quickdraw-identity` 保存，刷新页面后恢复，并显示保存提示。不会编造示例身份。

身份水印、界面文字和控件不画进用于识别的 Canvas，避免影响 CNN；失败样本 PNG 继续只导出画布内容。画板旁显示笔画/采样点数量，便于演示记录是否生效。
